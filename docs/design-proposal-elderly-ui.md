# LabelBuddy AI — 長者介面設計方案

> 設計者視角 · 2026-09-25
> 本方案以 `src/App.tsx` 的實際程式碼統計為基礎，非憑印象。

---

## 一、設計前提：長者不是「字放大的年輕人」

三項生理變化，各自對應一個設計決策：

| 生理變化 | 影響 | 設計對策 |
| --- | --- | --- |
| **水晶體黃化**（40 歲後） | 藍光被吸收，藍與綠、紫難分辨 | 少用藍色承載重要語意；藍色只做「可操作」 |
| **周邊視野縮減** | 餘光看到的面積變小 | 關鍵資訊集中中央主欄，不放角落 |
| **對比敏感度下降** | 淺灰字、細線看不見 | 正文對比 ≥ 7:1，不用淺灰當文字色 |

**推導出的三條鐵則：**

1. **一頁只問一件事** —— 長輩的工作記憶有限，多一件事就多一分放棄的機率
2. **顏色永遠搭配圖示與文字** —— 紅綠色盲在男性約 8%，不能只靠顏色傳達「能不能買」
3. **每一步都能一鍵返回** —— 「怕按錯就回不去」是長輩不用新工具的首要原因

## 二、現況稽核（以程式碼統計）

| 面向 | 現況 | 問題 |
| --- | --- | --- |
| 色彩 | `bg-blue-900` × 13、`bg-slate-100` × 11 | 沒有語意規則；紅＝危險又＝錯誤 |
| 邊框 | `border-4` × 16、`border-3` × 10 | 每張卡片都在「喊」，視覺噪音大 |
| 字級 | **15 種**（11～36px） | 相鄰級距太近，失去對比節奏 |
| 首頁 | 6 個區塊並列 | 身分條＋健康卡＋3 格指標＋拍照指引＋3 個測試鈕 |
| 除錯穿幫 | 「測試弱訊號語音」 | 給長者看到會困惑 |
| 已合格 | 主按鈕 72px、導航 67px | 超過無障礙下限，應保持 |

## 三、設計權杖（Design Tokens）

### 3.1 色彩：5 個角色，不再隨機

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 安全 | `#C0DD97` / 邊 `#3B6D11` | 安全、通過、已完成 |
| 注意 | `#FAC775` / 邊 `#854F0B` | 注意、適量、待確認 |
| 危險 | `#F09595` / 邊 `#A32D2D` | 危險、不建議、禁忌 |
| 操作 | `#B5D4F4` / 邊 `#185FA5` | 可按、進行中（唯一用藍） |
| 中性 | `#D3D1C7` / 邊 `#5F5E5A` | 背景、次要文字、分隔 |

### 3.2 字級：15 種 → 6 級

| 級別 | 大小 | 用途 |
| --- | --- | --- |
| 結論 | **34px** | 紅黃綠結論（全頁最大） |
| 標題 | 24px | 卡片標題 |
| 正文 | 20px | 主要閱讀文字 |
| 次要 | 17px | 說明、標籤 |
| 註解 | 14px | 補充資訊 |
| 最小 | 13px | 免責、來源標示（不再往下） |

### 3.3 邊框：從「都 4px」改為分層

| 粗細 | 用途 |
| --- | --- |
| **3px** | 只有結論卡與警示 |
| 1.5px | 一般內容卡 |
| 0.5px | 列表分隔、次要區塊 |

### 3.4 間距：8 的倍數，只用 4 級

`8px` 圖示與文字 · `16px` 卡片內距 · `24px` 卡片之間 · `32px` 區塊之間

## 四、四項關鍵設計決策

### 4.1 結果頁：三層金字塔（最重要）

**目前問題**：六張卡片同樣粗的邊框、同樣份量 → 沒有主角。

| 層級 | 回答的問題 | 內容 |
| --- | --- | --- |
| **第 1 層** | 「這包我能不能買？」 | 大字結論 + 紅黃綠 + 圖示 + 一句話，佔一屏 40% |
| **第 2 層** | 「為什麼？」 | 最多 3 項成分，用「佔每日上限 %」長條 |
| **第 3 層** | 想深入才展開 | 白話全文、營養表、食識卡（預設收合） |

**最關鍵的一步：把 mg 換成「佔每日上限幾 %」**

> 「鈉 2480 毫克」→ 長輩無法判斷多不多
> 「佔每日上限 124%」→ 一看就懂

這是整個設計中投報率最高的一項改動。

### 4.2 首頁：6 區塊 → 3 區塊

- 移除 3 個開發用測試按鈕（泡麵、燕麥、試聽語音）
- 身分條 76px → 56px（它是「確認」不是「操作」）
- 生理指標收進健康設定頁（偶爾才更新，不該天天佔位）
- 相機圖示放大到 **88px**，這是全頁唯一的動作

### 4.3 導航：雙行 → 圖示 + 單行

| 現在 | 改後 |
| --- | --- |
| 拍照辨識 / 健康設定 4項 / 飲食紀錄 6筆 / 食育學堂 | 拍照 / 健康 / 紀錄 / 學堂 |

- 圖示 24px + 文字，單行
- 選中項用「填色底 + 上方短線」雙重標示
- 縮成兩個字後，字級可從 15px 提到 18px

### 4.4 等待與錯誤：這是信任的關鍵時刻

**等待中**（目前只有轉圈圈，長輩 5 秒後就開始懷疑壞了）
- 三個具體步驟：照片收到 ✓ → 辨識成分（進行中）→ 對照健康設定
- 加上「通常需要 5 到 10 秒」讓等待有預期

**失敗時**（目前直接給錯誤碼）
1. 先說 **「不是您的問題」** 卸下焦慮
2. 給三個具體做法：光線照到、手靠貨架、標示入框
3. 最後給退路：**「用本機判斷（不需網路）」**

## 五、實作優先順序

| 優先 | 項目 | 理由 | 影響檔案 |
| --- | --- | --- | --- |
| **P0** | 結果頁 % 化 + 三層結構 | 直接影響「買不買」的正確判斷 | `App.tsx` |
| **P0** | 結論卡三重編碼（圖示+文字+色） | 色盲者目前讀不到結論 | `App.tsx` |
| **P1** | 首頁移除測試按鈕、收斂區塊 | 資訊過載是放棄主因 | `App.tsx` |
| **P1** | 等待中加步驟指示 | 直接減少中途放棄 | `App.tsx` |
| **P2** | 建立設計權杖並套用 | 一致性；降低後續維護成本 | 新增 `src/theme.ts` |
| **P2** | 導航改圖示 + 單行 | 提升辨識速度 | `App.tsx` |
| **P3** | 錯誤頁文案重寫 | 降低挫折感 | `App.tsx` |

## 六、驗證方式

改動後以既有工具驗證（零新增依賴）：

```bash
# 響應式：多寬度 × 多分頁
node <skill>/scripts/check-responsive-layout.mjs \
  --viewports "320x568,360x640,412x732" \
  --tabs "scan:#nav-tab-scan,conditions:#nav-tab-conditions,history:#nav-tab-history,classroom:#nav-tab-classroom"

# 手機框幾何（確認 360×640 內容區未跑掉）
node <skill>/scripts/check-phone-frame.mjs
```

**另建議加入的量化檢查**（目前專案沒有）：

1. **對比度檢查** —— 掃描所有文字節點的前景/背景，計算 WCAG 對比，低於 4.5:1 即報錯
2. **觸控目標檢查** —— 所有 `button` / `a` 的 `getBoundingClientRect()` 需 ≥ 48×48px
3. **色彩編碼檢查** —— 確認所有 `risk_level` 都同時有圖示與文字，不單靠顏色
