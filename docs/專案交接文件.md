## 3. 關鍵不變式（改動前必讀）

**這一章是整份文件最重要的部分。** 以下每一條都是踩過坑之後定下來的規則，
違反它們通常**不會報錯**，而是安靜地產生錯誤結果——對一個安全類 App 是最糟的失敗模式。

### 3.1 字級只能是 16 / 18 / 19 / 20px

`src/theme.ts` 的 `TYPE` 對照表：

| 名稱 | 值 | 用途 |
| --- | --- | --- |
| `conclusion` | `text-[20px]` | 頁面主標、結論 |
| `title` | `text-[19px]` | 卡片標題 |
| `emphasis` | `text-[18px]` | 強調數字、按鈕、徽章 |
| `body` | `text-[16px]` | **所有說明與敘述，字級地板** |
| `secondary` / `caption` / `micro` | 全部 = 16px | **`@deprecated` 別名**，保留只是為了讓舊呼叫點編譯得過 |

**鐵則**：

1. **16px 是地板。** 低於 16px 的免責文字對長者等於不可讀。
   要弱化某段文字請**改顏色**（`text-slate-600`），**不要縮字級**。
2. **級距只有 4px（16→18→19→20），相鄰兩級幾乎看不出差別。**
   → 「用字級表達重要性」這招**已經失效**。請改用
   **字重**（`font-black` vs `font-bold`）＋ **語意色** ＋ **位置**（中央主欄優先）。
3. **Emoji 不算文字**：用 `w-[Npx] h-[Npx] leading-none text-center` 控制大小，
   **不要用 `text-[Npx]`**。這樣「字級一律 16–20px」才能用 grep 機械驗證。

### 3.2 ⚠️ 兩個隱形違規：`text-xs` = 15px、`text-sm` = 17.5px

因為 `src/index.css` 有 `:root { font-size: 20px }`，Tailwind 所有 rem 尺寸**放大 1.25 倍**：

- `text-xs` → **15px**（低於地板，違規）
- `text-sm` → **17.5px**（不在 16–20px 的合法值中，違規）
- `p-4` → 20px、`w-9` → 45px、`gap-2` → 10px、`space-y-3` → 15px

**檢查字級時必須同時 grep 兩組**：

```bash
grep -rnE "text-\[[0-9]+px\]" src/          # 任意 px 值
grep -rnE "text-(xs|sm|base|lg|xl|2xl)" src/  # Tailwind 預設級距
```

**要精確尺寸一律用任意值**（`p-[12px]`、`min-h-[56px]`），不要用 rem 級距。

### 3.3 「佔每日上限幾 %」一律由後端重算

**最重要的原則：模型只讀出「含量」，百分比一律由後端重算。**

小型免費模型算 `2480 ÷ 2000 × 100` 會錯，而且**錯得無聲無息**。

- `server.ts` 的 `normalizeNutrientFacts(raw, numericLimits)`：
  用每日上限**覆蓋**模型算的 percent，補上 `dailyLimit` / `direction`，
  並統一過濾（**最多 3 項、只留 ≥ 30%**、依嚴重度排序）
- **三條路徑都要套用**：雲端成功、**快取命中**、本機備援
  （漏掉快取命中那條會回傳舊格式）
- 離線時由 `smartNutritionAnalyzer.ts` 的 `buildLocalNutrientFacts()` 接手
  → **離線時長條圖不會消失**

⚠️ **門檻是 30% 不是 50%**：50% 常讓對照表只剩 1 項，30% 才給得出 2～3 項。
⚠️ **limit 與 target 方向相反**：鈉 120% 是壞事、蛋白質 120% 是好事。
`NutrientFactBars.tsx` 的 `factTone()` 分開處理，**不可共用閾值**。

### 3.4 ⚠️ 後端用「中文子字串」比對，不是用 id

`server/smartNutritionAnalyzer.ts` 的規則引擎是用 **`.includes()` 比對中文名稱**，
不是比對 id。也就是說：

> **把某個慢性病名稱改到失去後端認識的關鍵字，離線備援引擎會靜默地不產生警示**
> ——不崩潰、不報錯，只是少一個警示。

這就是為什麼 §1.2 的 `conditions.ts` 名稱雖然「簡化成普通大家會用的字」，
但**每一個都保留了後端認識的關鍵字**（已用腳本驗證 12 項全部命中）。

**日後要改動 `conditions.ts` 的 `name` 欄位時，務必先跑一次關鍵字驗證。**

### 3.5 快取鍵必須含「身分」

`server.ts` 的回應快取鍵 = **圖片 SHA-256 + 慢性病清單 + 使用者身分**，TTL 24 小時。

**為什麼一定要含身分**：同一包高蛋白粉，對健身族是綠燈、對腎臟病患是紅燈。
少了身分這個維度，第二次查詢會拿到錯的結果。

（實測效益：5065ms → 7ms）

### 3.6 三重編碼鐵則

`RISK_TONE` / `RISK_ICON` / `RISK_LABEL` **必須一起用**。

理由：紅綠色盲在男性約 **8%**，只靠顏色等於讓這 8% 的人讀不到結論。
顏色 + 圖示 + 文字，三者缺一不可。

### 3.7 折行品質 ≠ 折行偵測

**不是所有折行都是問題。** 一句 18 字的中文在 360px 上本來就塞不進一行，
折成 2 行是**正確行為**，硬不讓它折反而會溢出。

真正該修的是這三類：

| 類別 | 判定 | 為什麼 |
| --- | --- | --- |
| **被擠壓折行** | 實際行數 > `ceil(估算文字寬 ÷ 可用寬)` | 明明塞得下卻折行 → 排版被擠壓 |
| **孤行 orphan** | 末行 < 3 字且非句尾標點 | 長者要回頭掃那 1～2 個字，代價很高 |
| **行數過多** | ≤22 字的句子折 ≥4 行 | 欄寬太窄或字太大 |

**驗證工具**：`check-wrapping-quality.mjs`（見 §9）。
⚠️ 舊的 `check-responsive-layout.mjs` 把**任何多行**都當問題 → 255 筆假警報，**別再用它驗折行**。

**三個常見的擠壓根因與解法**：

1. `flex` 子項預設 `min-width: auto` → 被最長一行撐寬，擠掉同層元素。
   **解法：加 `min-w-0`。**
2. 一行塞太多東西（標籤 + 2 個按鈕）→ **解法：改 `flex-col` 上下堆疊或加 `flex-wrap`。**
3. flex 自動分配的欄寬不可預期 → **解法：改用 `grid-cols-[30px_1fr]` 固定欄寬。**

⚠️ **`flex-wrap` 不是萬靈丹**：實測在慢性病清單的列上加 `flex-wrap`，
會讓名稱與徽章變成上下堆疊、列高從 56px 暴增到約 100px。
正確解法是**移除 `flex-wrap`，改成在名稱 span 加 `whitespace-nowrap`**。

⚠️ 有些標籤**本來就該強制單行**：`nowrap`（避免被擠壓）＋ 外層 `flex-wrap`（避免溢出）。
目前已加：導航標籤、狀態徽章、快選膠囊、單位切換鈕、篩選 chips。

### 3.8 桌機「手機框」的四個連帶必改處

使用者手機是 16:9 直向（CSS 視窗 360×640，DPR 3）。
桌機版用 `min-[520px]:` 斷點包手機框（**<520px 完全不套用，零回歸**）。

- 外框 `w-[380px] h-[660px]`（border-box）→ **內容區剛好 360×640**
  ⚠️ 若設 `w-[360px]`，內容區只剩 340px，導航按鈕會從 83px 縮到 78px

**漏改就會壞的 4 處**：

1. **overlay 必須寫 `fixed inset-0 min-[520px]:absolute`**（**不可只寫 `absolute`**）
   - `App.tsx` 的 Loading 遮罩、`DietHealthHistory.tsx` 的匯出彈窗
   - ⚠️ 手機容器是 `min-h-screen`，內容長時**比視窗高**；只寫 `absolute`
     會以「文件」為基準置中 → spinner 掉出視窗外（實測 y≈560）
2. footer 的 `sticky bottom-0` → 改 `shrink-0`
3. 主內容容器加 `min-h-0 min-[520px]:overflow-y-auto`
4. 移除內層 `max-w-md mx-auto`（nav / footer）

**固定列實測合計約 270–274px**（header 92～95 + nav 86～87 + footer 92）；
底部 CTA `min-h-[72px] text-[20px]`。

### 3.9 捲動容器隨寬度改變

- **360px**：捲動的是 **window**
- **≥520px**：`<main>` 才是捲動埠（`min-[520px]:overflow-y-auto`）

寫截圖／自動化腳本時**兩種都要處理**，否則會出現「怎麼捲都拍到頁面頂端」。

### 3.10 觸控尺寸

- 整列（56px）就是勾選目標，符合 48×48 最低觸控規範
- 展開鈕必須是**獨立的** `grid-cols-[1fr_48px]` 儲存格，尺寸 `min-h-[56px] w-[48px]`
- 44px 勾選框是**純視覺**，要加 `pointer-events-none`

## 5. 環境限制與已知問題

### 5.1 ⛔ Google Gemini 區域封鎖（已定案，不必重查）

使用者在**中國澳門**。Google Gemini API 官方支援區域**不含中國澳門／中國香港／中國大陸**。

- 實際呼叫回 `400 FAILED_PRECONDITION: User location is not supported for the API use.`
- **三把**不同金鑰、不同帳號皆相同結果 → 換帳號無用
- 實驗證明檢查順序是「身分 → 金鑰 → 區域（依呼叫來源位置）」
- 對照組：無效金鑰回 `400 API_KEY_INVALID`（證明網路通）；無金鑰回 `403 unregistered callers`
- **唯一合規解法**：後端部署到支援區域（Vercel／中國台灣／新加坡）
  → 免費額度 50/日 變約 1550/日（×31）
- 現況：以 **OpenRouter 為主力**；Gemini 程式碼保留，遇區域錯誤自動冷卻 6 小時
- ⚠️ 用 VPN 或謊報地區繞過屬服務條款問題，**不建議**

### 5.2 模型鏈（會變動，失敗時先重查）

`server.ts` 的 `DEFAULT_MODEL_CHAIN`（**上限 3 個**）：

| 模型 | 實測 | 特性 |
| --- | --- | --- |
| `dots-studio/dots-3-note-preview:free` | 1.6～2.3 秒 | 品質最佳 |
| `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` | 0.6 秒 | 最快、敘述精簡 |
| `qwen/qwen3.8-27b:free` | 常 429 | 備援 |

⚠️ **OpenRouter 的 `models` 降級陣列上限 3 個**，放 4 個會回
`400 'models' array must have 3 items or fewer`。`getModelChain()` 已 `.slice(0, 3)`。

⚠️ **免費模型會變動**：雲端突然失敗時，先查 `GET /api/v1/models`，
過濾 `pricing.prompt == 0` 且 `input_modalities` 含 `image`。

⚠️ **除錯陷阱**：OpenRouter 會快取相同請求 →「重複測試看起來很快」但真實請求慢得多。
**驗證延遲時務必在提示詞加唯一編號避開快取。**

### 5.3 ⚠️ 小型免費模型的中文字元不可靠（尚未完全解決）

判斷結論與數字可靠，但**個別中文字會錯**
（同一個「鈉」出現鈣／鈦；「無糖」變「低鈣」）。

- 已做：提示詞術語規則、簡繁後處理
- **無法用字串修**：鈉→鈦 是同音形近的**字元替換**，不是簡繁問題
- **建議**：正式上線改付費模型，`.env` 設 `OPENROUTER_MODEL` 即可切換，**程式不用改**

### 5.4 簡繁後處理

`server.ts` 的 `SIMPLIFIED_TO_TRADITIONAL` **只收「簡繁一對一無歧義」的字**
（后／後、干／乾、里／裡、面／麵、只／隻、发／發／髮 一律不列，避免把正確的字改壞）。

目前約 130 字。**日後又看到簡體字，先查是不是新字不在表內，別急著換模型。**

## 6. 額度與供應商策略

使用者要求「兩個一起用，不要很快用完」。已實作四層機制：

1. **雙供應商輪替**：`orderedProviders()` 依「今日已用 / 每日上限」比例排序
2. **健康冷卻**：一般失敗連續 2 次 → 冷卻 10 分鐘；
   永久性錯誤（區域封鎖）→ **立即冷卻 6 小時**
3. **回應快取**（最有效）：TTL 24 小時、上限 200 筆
4. **額度預檢**：`getOpenRouterQuota()` 查 `GET /api/v1/key`（快取 60 秒、不耗額度），
   `remaining == 0` 時直接跳過

### 相關常數（`server.ts`）

| 常數 | 值 |
| --- | --- |
| `PORT` | `3000`（可用環境變數覆寫） |
| `MAX_MODEL_CHAIN` | `3` |
| `DAILY_QUOTA` | `{ gemini: 1500, openrouter: 50 }` |
| `COOLDOWN_MS` | `10 * 60 * 1000` |
| `REGION_BLOCK_COOLDOWN_MS` | `6 * 60 * 60 * 1000` |
| `CACHE_TTL_MS` | `24 * 60 * 60 * 1000` |
| `CACHE_MAX_ENTRIES` | `200` |

### ❌ OpenRouter 額度：多開金鑰／帳號無效

官方明文：「Making additional accounts or API keys will not affect your rate limits,
as we govern capacity globally.」→ 額度是**全域治理**，多開違反服務條款。

| 累計購買點數 | 每分鐘 | 每日 |
| --- | --- | --- |
| 未購買 | 20 | **50** |
| ≥ 10 點數 | 20 | **1000** |

- 真實用量看 `GET /api/v1/key` 的 **`free_model_daily_requests`**（`{used, limit, remaining}`），
  `limit_reset: "daily"` → 每日重置
- ⚠️ 同回應中的 `limit` / `limit_remaining` 是 **per-key 信用上限**，不是免費請求數（易混淆）
- **唯一合法提升方式**：一次性買 ≥ 10 點數（累計）→ 50/日 變 1000/日

### APK 打包的架構限制（2026-09-24 評估）

**前端 `fetch('/api/analyze-label')` 用相對路徑，且 API 金鑰只在後端**
→ **純離線 APK 會讓雲端辨識完全失效**，APK 必須指向一個後端。

- 本機**完全沒有** JDK / Android SDK / Gradle 快取；Node 22.22.2、網路全通
- 建議工具鏈裝 `D:\android-dev\`（D 槽空間充裕）
- Capacitor：`@capacitor/android` 8.5.2、minSdk 24、compileSdk/targetSdk 36、
  AGP 8.13.0、Gradle 8.14.3；JDK Adoptium Temurin 21.0.12+101.0.LTS

**三個方案**：

1. **Capacitor APK + Vercel 後端**（推薦，且能讓 Gemini 復活 ×31）
2. **PWA**（零工具鏈，但不是 `.apk`）
3. **真離線 APK**（工程量大，且金鑰可被反編譯）

⚠️ **Vercel 風險**：檔案系統唯讀（快取重啟即清）、請求上限 4.5MB、
執行時間限制、金鑰必須存環境變數不進 Git。

### 環境陷阱（沙箱內）

- `package.json` 的 `esbuild` 必須 ≥ `^0.28.0`，否則 `npm install` 會 ERESOLVE（vite 8.3.0 peer）
- `npm start` 需搭配 `NODE_ENV=production`，否則會以開發模式啟動並嘗試載入 Vite 中介軟體
- 環境變數檔名必須是 `.env`（`dotenv.config()` **不讀** `.env.local`）

- ⚠️ **殘留的 `node.exe` 佔用 3000 埠時，會服務「舊程式碼」**，
  造成幽靈般的驗證失敗。驗證前先確認埠上沒有舊行程。
- ⚠️ 沙箱內 `curl` 會走 `HTTP_PROXY`，**無法連 localhost** → 改用 Node 的 `fetch`
