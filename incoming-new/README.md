## 這是什麼

一套**多族群食育學習平台**。它不只是「幫你判斷這包能不能買」的工具，而是一間可以帶進超市的行動教室：
每次掃描除了給結論，還會教一個**可以帶去下一包使用的營養觀念**，
讓學習者逐步建立「不靠工具也能自己看懂包裝」的能力。

## 為什麼要分族群

同一包餅乾，對 70 歲高血壓長者、對增肌中的健身族、對趕時間的年輕外食族、對正在學營養的學生，
意義完全不同。食育不該只有一套標準答案，因此本平台以**學習者身分**為軸：

| 身分 | 最在意 | 每日糖上限 | 教學重點 |
| --- | --- | --- | --- |
| 🧓 長者與三高族群 | 鈉、糖、飽和脂肪、蛋白質 | 50 g | 鈉與糖的化名、防肌少症的蛋白質 |
| 💪 健身增肌減脂族 | 蛋白質效率、熱量密度、隱藏糖 | 25 g | 「高蛋白」宣稱陷阱、蛋白質／熱量比 |
| 🧑‍💻 年輕外食族 | 添加糖、鈉、加工程度 | 50 g | 糖換算方糖、鈉藏在醬料湯汁 |
| 🎒 學生與食育學習者 | 添加物、原型食物、纖維 | 25 g | 添加物功能分類、成分表長度 |

切換身分會連動改變：AI 的角色語氣與比對重點、每日參考值、知識卡庫、測驗題、結果頁的教學欄位。

## 教學設計：六階段鷹架式學習路徑

本平台的課程不是知識的羅列，而是依教學理論設計的學習路徑（見 `src/data/educationContent.ts` 的 `TEACHING_DESIGN`）：

| 階段 | 對應功能 | 教學原理 |
| --- | --- | --- |
| ① 建立認知錨點 | 每日參考值速查 | 前導組織（Advance Organizer） |
| ② 學會可操作程序 | 讀標籤三步驟 | 程序性知識示範 |
| ③ 理解背後原理 | 食育知識卡庫 | 意義化學習 |
| ④ 預測與驗證 | 先自己判斷，再讓 AI 對答案 | 預測—觀察—解釋（POE） |
| ⑤ 形成性評量 | 食育小測驗（答完立即解說） | 形成性評量與即時回饋 |
| ⑥ 歷程反思 | 學習與把關週紀錄 | 學習歷程檔案（Portfolio） |

核心方法是「**先預測、再對照**」：讓每次掃描都成為一次認知衝突與概念修正的機會。

## 資料安全與隱私（Privacy by Design）

「用 AI 分析就要把照片上傳雲端」是本平台正面回應的問題：

| | 🔒 本機模式（預設） | ☁️ 雲端 AI 增強模式 |
| --- | --- | --- |
| 照片去向 | 不離開裝置 | 傳送至 Google Gemini |
| 是否需同意 | — | **需明確勾選同意，可隨時撤回** |
| 教育內容 | 完整（三個教學欄位都有） | 完整 |
| 離線可用 | ✅ | ❌ |

- **預設最保守**：不主動啟用雲端，由內建食育引擎完成分析與教學
- **明示同意**：切換雲端前跳出同意彈窗，逐項列出「會上傳什麼／傳到哪裡／不會上傳什麼」
- **資料最小化**：只上傳壓縮後的標籤照片（1024px JPEG），不含學習紀錄與健康設定
- **伺服器無狀態**：不寫入資料庫、不保存圖片與分析結果，僅記憶體即時處理
- **可撤回、可清除**：隨時切回本機模式，或一鍵清除本機所有資料
- **機器可讀的揭露端點**：`GET /api/privacy` 提供完整的資料處理說明

> 重點：**教育內容不會因為選本機模式而縮水**。兩種模式產出完全相同的三個教學欄位，
> 因此可以全程使用本機模式完成所有學習。

## 四大分頁

1. **📸 拍照辨識** — 先自己判斷，再讓 AI 對答案。
   結果頁附「這一包，學到什麼？」食育知識卡：① 為什麼要緊 ② 下次我怎麼自己看 ③ 對照每日參考值，
   並標示本次分析是「本機引擎」還是「雲端 AI」。
2. **📚 食育學堂** — 課程導言與學習目標、教學設計說明、每日參考值、讀標籤三步驟、
   知識卡庫、形成性評量小測驗，全程語音朗讀。
3. **🩺 學習設定** — 學習者身分、生理指標量測、健康關注項目、資料安全與隱私。
4. **📊 學習紀錄** — 同時是把關紀錄與**學習歷程檔案**：A/B/C 評級、三色統計、
   「本週學會的營養知識」，並可匯出週報分享。

## 教育內容從哪裡來

- **雲端模式**：Gemini 在分析標籤的同時產出三個教學欄位，提示詞依身分動態組裝
  （見 `server.ts` 的 `buildSystemInstruction()`）。
- **本機模式**：`server/smartNutritionAnalyzer.ts` 的 `buildEducationContent()`
  依身分與實際營養數字，換算成「吃掉幾成每日額度」，並挑出對應的知識點與讀標籤技巧。
- **靜態知識庫**：`src/data/educationContent.ts`（19 張知識卡、14 題測驗、3 步驟、教學設計）
  與 `src/data/learnerProfiles.ts`（四種身分的每日參考值與學習目標）。

> 每日參考值以成人 2000 大卡為基準，參考台灣衛福部國健署、WHO 游離糖與鈉攝取建議，
> 以及運動營養學界對蛋白質攝取的共識區間。慢性病與特殊訓練目標請以醫師與營養師建議為準。

## 無障礙設計

- 單欄垂直滾動，無橫向並排欄位
- 觸控目標全面 ≥ 60px，底部主按鈕 ≥ 80px
- 基礎字體 20px、標題 28px、警示 36px 粗體
- 全程 Web Speech API 語音朗讀（粵語優先，自動降級國語）
- 拍照震動回饋、弱訊號語音安撫、429 友善提示

## 本機執行

**前置需求：** Node.js

```bash
npm install
# 於 .env.local 設定 GEMINI_API_KEY（選用；未設定時自動使用本機引擎）
npm run dev
```

| 指令 | 說明 |
| --- | --- |
| `npm run dev` | 開發模式（Express + Vite middleware，http://localhost:3000） |
| `npm run lint` | 型別檢查（`tsc --noEmit`） |
| `npm run smoke` | 執行期渲染驗證 + 把關邏輯回歸測試（四身分課程、隱私面板、內容資料庫） |
| `npm run comparison` | 產出 `docs/profile-comparison.html`：同一包食品 × 四身分的教學輸出對照素材（需先啟動伺服器） |
| `npm run build` | 正式建置（前端 bundle + `dist/server.cjs`） |
| `npm start` | 正式模式啟動（`scripts/start.cjs` 會設定 `NODE_ENV=production`，服務 `dist/`） |

### 比賽用對照素材

`npm run comparison`（需先 `npm start` 或 `npm run dev`）會呼叫本機 API，
把「三種食品 × 四種學習者身分」的完整教學輸出抓下來，產出
`docs/profile-comparison.html`。內容包含：

- 同一包紅燈泡麵在四種身分下的四套教學內容（白話摘要／為什麼／怎麼看／每日參考值）
- 每日參考值確實依身分改變的數據表（長者糖上限 50g vs 健身 25g）
- 六階段教學設計與隱私架構對照
- 驗證證據

該頁面為純靜態 HTML，可直接開啟簡報或列印為 PDF。全程使用 `localOnly: true`，未上傳任何資料。
