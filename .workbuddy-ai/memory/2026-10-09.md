# 2026-10-09 — 修掉「收起音量面板後摘要不更新」的同步 bug

## 🐛 使用者回報
> 「當我調整音量後關閉音量控制面板，外部的音量顯示數值不會同步更新。」

## 根因（單一數值有兩個來源）

`SettingsSection` 的收合摘要 `summary` 是**父層（App.tsx）算出來的 prop**：

```tsx
<SettingsSection summary={t('settings.sound.summaryOn', { n: Math.round(ttsSettings.volume * 100) })}>
  <TtsVolumeSection key={ttsSettings.volume} />
</SettingsSection>
```

但 `ttsSettings` 這個 state **只在兩個地方更新**：
1. `handleChangeProfile()`（切換身分）
2. `useEffect(..., [learnerProfileId])`（掛載 ＋ 身分變動）

而 `TtsVolumeSection` **沒有 props、沒有回呼** —— 它自己 `useState(volume)`，
只呼叫模組層的 `setTtsVolume()`（寫 localStorage ＋ 模組 cache）。
**父層完全不知情。**

★ 那個 `key={ttsSettings.volume}` 的註解寫著「使用者在滑桿放手後，區塊會以新值重建」——
**是一個從未成立的假設**：`ttsSettings.volume` 永遠不變，所以 key 永遠不變。

## 觸發路徑（面板關閉後才看得到）

1. 拖動 `#tts-volume` → `changeVolume()` → 只改**子元件自己的 state** ＋ 模組層儲存
2. 沒有任何呼叫端通知 App.tsx → `ttsSettings` **不變**
3. 點 header 收起 → `SettingsSection.setIsOpen(false)` → **只有 SettingsSection 自己重繪**
4. App.tsx **沒有重繪** → `summary` 還是舊的 prop → 顯示舊百分比
   （切分頁也不會好：state 的值沒變，只是重新 render）

## 修正

**改成受控元件**（父層是唯一來源）：
- `TtsVolumeSection` → `{ value, onChange }`，移除內部 `volume` state
- `TtsVoiceLangSection` → `{ value, onChange }`（**同一個 bug，使用者沒提到但一模一樣**）
- App.tsx：`onChange={(v) => setTtsSettingsState(setTtsVolume(v))}`
- 移除那兩個**從未生效**的 `key` 假解法

★ 附帶修掉：語言摘要原本讀 `ttsSettings.voiceLang`（`null` 時顯示「粵語」），
但子元件用的是「跟隨介面語言」（英文介面＝English）→ **兩邊不一致**。
改成兩邊都用 `resolveVoiceLang(language)`。

## ★★ 變異測試（證明斷言不是假通過）

新增 2 條斷言後，**先還原舊版**跑一次（`git stash push -- <兩個檔案>`）：

```
❌ 收起「音量」面板後… → 摘要為「音量 80%」，預期含 45%
❌ 收起「朗讀語言」面板後… → 摘要為「粵語」
```

**80% 正是掛載時的長者預設值** —— 直接證實了「摘要停在掛載時的值」。
修正後兩條都 ✅。`check:tts` **45 通過 / 0 失敗 / 1 跳過**。

## 教訓
- **同一數值只能有一個來源**。父層要顯示、子元件要編輯 → 就用受控元件；
  兩個 state 各存一份，遲早漂移，而且**只有某個特定操作順序才看得到**。
- **假解法比沒有解法更糟**：那個 `key` 的註解寫得像已經處理了，
  讓後來的人（包括我）以為這條路已經通了。
- 又一次「改了一處、另一處沒改」：語言那一格有完全相同的 bug，
  使用者只回報了音量。
