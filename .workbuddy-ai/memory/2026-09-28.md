### ★ 核心技巧：用「相容層」避免重寫 handler
原本 6 個 handler 綁死在 `app.post('/api/...', async (req, res) => {...})`。
用極薄的 `makeRes()` 包住，**handler 內容幾乎不動**：
- `req.body` → 傳入的 `body` 參數
- `res.json(x)` / `res.status(s).json(x)` → 回傳 `{ status, json }`

**關鍵**：`res.json()` **回傳「結果物件」而不是 res 本身**。
因為原本寫法是 `return res.json(...)`，讓 json() 直接回傳結果，
那些 return 就能原封不動運作。
（實際只需處理 **18 個 `res.`** 與 **6 個 `req.`**）

### ★ 依賴注入：讓 Worker 不必打包 tesseract.js
`server/core.ts` **絕對不能** import Node 模組（fs/path/os）或 tesseract.js
—— Worker 打包會直接失敗。伺服器端 OCR 改由呼叫端注入：
```ts
export interface CoreDeps {
  recognizeImage?: (base64: string) => Promise<OcrRecognitionResult>;
}
```
- Express 提供真的實作
- Worker **不提供** → handler 回 `OCR_NOT_AVAILABLE`（明確回報比默默失敗好）

### ★★ 沙箱踩到的坑
1. **`npx` 會觸發 safe-delete 保護**
   `npx wrangler` 找不到本機安裝時會下載到 `npm-cache\_npx\`，
   失敗後的回滾刪除會撞上 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（門檻 50 檔案），
   洗出上百行 `npm warn cleanup`。
   → **對策：用本機執行檔** `node node_modules/wrangler/bin/wrangler.js`，不要用 `npx`。
2. **`miniflare` 需要 `ws` 模組**，`npm install wrangler` 不會自動帶上，要另外裝。
3. **`npm install --save-dev wrangler` 會回滾**，package.json 沒寫入成功
   → 手動補 `"wrangler": "^4.142.0"` 到 devDependencies。
4. **抽取程式碼時的邊界陷阱**：
   - 切在註解中間 → 留下未閉合的 `/**`（`TS1010: '*/' expected`）
   - `SYSTEM_INSTRUCTION_INDICATORS` / `_HEALTH_QA` 定義在 handler **之間**，
     抽取 core（只取第一個 handler 之前）時被漏掉 → 從 git 找回
   - 批次加 `export` 的正則**漏了「非 async 的 function」** → 10 個符號沒加上
