### ★★ 批次 4 為什麼撤回（重要，別再重做一次）
做完 `git rm --cached` 之後要推送時，發現**推送被拒**：本機落後 `origin/main` **21 個提交**。
追查後確認 —— **另一個 AI 是在「另一個 clone」工作，透過 GitHub 同步**（它的提交裡有
「合併 origin/main（另一個 AI 的 6 筆）並解決記憶檔衝突」，代表它也得合併我的提交）。

→ 這代表 `.workbuddy-ai/memory/` 與 `AI_COLLAB.md` **不是「開發過程紀錄」，而是兩個 clone 之間的
共享記憶與溝通管道**。把它們移出版控的後果是：
**另一個 clone 下一次 `git pull` 會把這些檔案從它的硬碟上刪掉 → 它會直接失去整個專案記憶。**

→ 因此**撤回批次 4**，`.gitignore` 的三行也一併還原。`docs/` 理論上可移出，但同樣會刪掉
對方硬碟上的 `專案交接文件.pdf`，且兩個 clone 各自 `git add -A` 時會反覆翻轉（檔案已存在對方
索引中，`.gitignore` 對已追蹤檔案無效）→ **一起撤回，改為先問使用者**。

★ **教訓**：本專案有兩個 clone。**任何「把檔案移出版控」的動作都要先確認對方 clone 的狀態**，
否則等於遠端刪檔。
